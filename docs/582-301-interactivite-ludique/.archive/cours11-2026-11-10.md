### Le build Windows

!!! info "Pas exigé à l'alpha, mais recommandé"
    Le build Windows n'est demandé qu'à la remise finale : le dossier du build dans le `.zip`, avec le lien du répertoire GitHub et celui de la page itch.io. Le faire une première fois aujourd'hui permet de voir comment ça se passe, plutôt que de le découvrir la veille de la remise.

1. Dans **Build Profiles**, sélectionner **Windows**, puis **Switch Platform** si elle n'est pas déjà active
1. Cliquer **Build**
1. Créer un dossier `Builds/Windows` **à la racine du projet**, à côté du dossier `Assets` (jamais dedans)
1. Une fois le build terminé, lancer le `.exe` et jouer du début à la fin : accueil, trois niveaux, fin, crédits, retour à l'accueil

!!! warning "Le `.exe` seul ne fonctionne pas"
    Le jeu, c'est **tout le dossier** : le `.exe`, le dossier `_Data`, `UnityPlayer.dll`, etc. C'est ce dossier complet qui va dans le `.zip` de remise du projet final (`build-windows`).

!!! info "Et Git?"
    Le `.gitignore` Unity standard ignore déjà le dossier `Builds/` : les builds ne vont pas dans le répertoire GitHub.

## WebGL

### Ton jeu devient une page web

Unity peut compiler le jeu pour le **navigateur** : le code est traduit en WebAssembly, le rendu passe par WebGL. Le résultat est un dossier de fichiers web : `index.html`, `Build/`, `TemplateData/`. Plus de téléchargement, plus d'installation : un lien, et on joue.

**Le module Web**

1. Dans **Unity Hub** : **Installs**, icône ⚙️ de la version utilisée > **Add modules**
1. Cocher **Web Build Support** > **Install**
1. Redémarrer Unity

**Le build**

1. Dans **Build Profiles**, sélectionner **Web** > **Switch Platform**
1. Cliquer **Build** et choisir un dossier `Builds/Web` à la racine du projet
1. ⏳ Compter de **5 à 20 minutes**. Unity est bloqué pendant ce temps : c'est le moment de préparer la page itch.io et le README

!!! tip "Tester sur son poste"
    Double-cliquer sur `index.html` ne fonctionne pas : le navigateur refuse de charger les fichiers sans serveur. **Build And Run** lance un petit serveur local et ouvre le jeu dans le navigateur.

### Les contraintes : pas de fenêtres natives, compression, taille

| Contrainte | Conséquence |
|---|---|
| **Pas de fenêtre native** | `Application.Quit()` ne fait rien : un onglet de navigateur ne se ferme pas tout seul. Le bouton **Quitter** doit disparaître (voir plus bas) |
| **Le son attend un clic** | Le navigateur bloque le son tant que le joueur n'a pas cliqué dans la page. L'écran d'accueil règle le problème : le clic sur **Jouer** débloque l'audio |
| **La souris verrouillée** | Le navigateur exige un clic dans le jeu avant de verrouiller la souris, et **Échap** la libère toujours |
| **La taille** | Tout le jeu est téléchargé avant de démarrer : chaque Mo se paie en temps de chargement |
| **La performance** | Le jeu tourne moins vite que le build Windows : les lumières et les ombres coûtent plus cher (voir [La performance](#la-performance)) |

**La compression**

Unity compresse le build Web pour qu'il se télécharge plus vite. Le réglage est dans **Edit > Project Settings > Player**, onglet **Web** > **Publishing Settings** :

| Réglage | Valeur |
|---|---|
| **Compression Format** | `Brotli` (par défaut) : itch.io le prend en charge |
| **Decompression Fallback** | **Coché** : le jeu se décompresse lui-même si le serveur ne s'en charge pas. Un peu plus lent au chargement, mais fonctionne partout |

### Les pièges fréquents

| Symptôme | Cause | Solution |
|---|---|---|
| Écran noir ou erreur *Unable to parse Build/…* | Le serveur ne sait pas lire la compression | Cocher **Decompression Fallback**, refaire le build |
| La barre de chargement prend une éternité | Build trop lourd | Musique en streaming, textures réduites (voir [La performance](#la-performance)) |
| Rien ne se passe au changement de scène | Scène absente de la **Scene List** | Voir [l'erreur classique](#les-scenes-incluses-et-lerreur-classique) |
| Le bouton Quitter ne fait rien | `Application.Quit()` est ignoré sur le Web | Le cacher avec le script ci-dessous |
| Pas de son au démarrage | Le navigateur attend un clic | Un écran d'accueil avec un bouton |
| Le HUD est coupé ou déborde | Le Canvas ne s'adapte pas | **Canvas Scaler** en `Scale With Screen Size` (voir le [cours 5](./cours05.md)) |
| Échap n'ouvre pas le menu pause | Le navigateur garde Échap pour libérer la souris | Une deuxième touche de pause (voir [Le menu pause](#le-menu-pause)) |

**Cacher le bouton Quitter sur le Web**

1. Ajouter le script sur le bouton **Quitter** du menu d'accueil

```c# title="CacherSurWeb.cs"
using UnityEngine;

public class CacherSurWeb : MonoBehaviour
{
    void Awake()
    {
        // Dans un navigateur, on ne quitte pas : on ferme l'onglet
        if (Application.platform == RuntimePlatform.WebGLPlayer)
            gameObject.SetActive(false);
    }
}
```

## Le menu pause

Mettre le jeu en pause, c'est figer le temps : `Time.timeScale` règle la vitesse à laquelle le temps s'écoule dans Unity. C'est le même outil que le [*hit stop* du cours 10](./cours10.md#le-hit-stop), mais tenu à `0` jusqu'à ce que le joueur reprenne.

| Valeur | Effet |
|---|---|
| `1` | Vitesse normale |
| `0.5` | Ralenti |
| `0` | Temps figé : la physique, les animations et tout ce qui dépend de `Time.deltaTime` s'arrêtent |

!!! warning "Ce que `timeScale` n'arrête pas"
    - `Update()` continue d'être appelée : un code qui ne se sert pas de `Time.deltaTime` continue de tourner.
    - L'interface (boutons, survol) reste cliquable, heureusement.
    - Le son continue de jouer. Pour l'étouffer, passer par un snapshot de l'Audio Mixer (voir les [snapshots du cours 7](./cours07.md#snapshots-contextes)); pour le couper, `AudioListener.pause = true;`.
    - Avec les Starter Assets, la caméra suit encore la souris : le mouvement de la souris n'est pas multiplié par `Time.deltaTime`.

!!! warning "Échap dans le navigateur"
    Sur le Web, le navigateur garde la touche **Échap** pour libérer la souris : le premier appui rend le curseur, mais n'ouvre pas toujours le menu. Le script accepte donc aussi **P**. Le dire au joueur dans les commandes.

#### Monter le menu

1. Dans le **Canvas** du niveau, créer un **Panel** nommé `MenuPause`
1. Y ajouter un titre (TextMeshPro) et deux boutons : **Reprendre** et **Accueil**
1. Désactiver `MenuPause` (case à cocher en haut de l'**Inspector**) : il est caché au démarrage
1. Ajouter le script ci-dessous sur le **Canvas** (pas sur `MenuPause` : un objet désactivé n'exécute pas son `Update`), puis glisser `MenuPause` dans **Menu Pause**
1. **On Click** du bouton Reprendre → `GestionPause.Reprendre`; du bouton Accueil → `GestionPause.RetourAccueil`

```c# title="GestionPause.cs"
using UnityEngine;
using UnityEngine.InputSystem;
using UnityEngine.SceneManagement;

public class GestionPause : MonoBehaviour
{
    public GameObject menuPause;          // Glisser le Panel MenuPause ici
    public string sceneAccueil = "Accueil";

    bool enPause = false;

    void Update()
    {
        // Échap ou P (nouveau Input System, comme les Starter Assets)
        if (Keyboard.current.escapeKey.wasPressedThisFrame || Keyboard.current.pKey.wasPressedThisFrame)
        {
            if (enPause) Reprendre();
            else Pause();
        }
    }

    public void Pause()
    {
        enPause = true;
        menuPause.SetActive(true);
        Time.timeScale = 0f;
        Cursor.lockState = CursorLockMode.None;
        Cursor.visible = true;
    }

    public void Reprendre()
    {
        enPause = false;
        menuPause.SetActive(false);
        Time.timeScale = 1f;
        Cursor.lockState = CursorLockMode.Locked;
        Cursor.visible = false;
    }

    public void RetourAccueil()
    {
        Time.timeScale = 1f; // Sinon la scène suivante démarre figée !
        SceneManager.LoadScene(sceneAccueil);
    }
}
```

## Le menu Options : le volume

Le projet final n'exige pas de curseur de volume, mais c'est un réglage que les joueurs apprécient. Il s'appuie sur l'Audio Mixer `MixerPrincipal` et ses groupes, montés au [cours 7](./cours07.md#laudio-mixer).

### Exposer le volume d'un groupe

1. Ouvrir `MixerPrincipal` et cliquer sur le groupe `Musique`
1. Dans l'**Inspector**, clic-droit sur le mot **Volume** > **Expose 'Volume (of Musique)' to script**
1. En haut à droite de la fenêtre **Audio Mixer**, menu **Exposed Parameters** : double-cliquer sur `MyExposedParam` et le renommer `VolumeMusique`
1. Répéter pour `SFX` (`VolumeSFX`)

### Le slider

1. Dans le panneau Options, clic-droit **UI (Canvas) > Slider**
1. Ajouter le script ci-dessous, glisser `MixerPrincipal` dans **Mixer**, **Parametre** = `VolumeMusique`

```c# title="SliderVolume.cs"
using UnityEngine;
using UnityEngine.Audio;
using UnityEngine.UI;

[RequireComponent(typeof(Slider))]
public class SliderVolume : MonoBehaviour
{
    public AudioMixer mixer;                  // Glisser MixerPrincipal ici
    public string parametre = "VolumeMusique"; // Le nom exact du paramètre exposé

    Slider slider;

    void Start()
    {
        slider = GetComponent<Slider>();
        slider.minValue = 0.0001f;            // Jamais 0 : Log10(0) n'existe pas
        slider.maxValue = 1f;
        slider.value = PlayerPrefs.GetFloat(parametre, 1f);  // Dernier réglage, sinon plein volume
        slider.onValueChanged.AddListener(Changer);
        Changer(slider.value);
    }

    void Changer(float valeur)
    {
        mixer.SetFloat(parametre, Mathf.Log10(valeur) * 20f);  // 0 à 1 → -80 dB à 0 dB
        PlayerPrefs.SetFloat(parametre, valeur);
    }
}
```

!!! warning "Pourquoi `Log10` et pas la valeur directe"
    Le mixer compte en **décibels** : `0 dB` = volume normal, `-80 dB` = silence. L'oreille n'entend pas le volume de façon linéaire : envoyer la valeur du slider telle quelle donnerait un curseur qui ne change presque rien sur 80 % de sa course, puis coupe tout d'un coup. `Log10(valeur) * 20` répartit le changement sur toute la course.

!!! tip "Un son de test"
    Sur le slider `SFX`, dans **On Value Changed**, cliquer **+**, glisser un objet qui porte une **Audio Source** (un son court, groupe **Output** = `SFX`) et choisir **AudioSource > Play ()**. Le joueur entend tout de suite le volume qu'il règle.

## La sauvegarde

!!! info "Tu sauvegardes déjà, depuis le cours 3"
    La case **Persistent** d'une Variable du CES écrit sa valeur sur le disque et la recharge au lancement suivant. Tu t'en sers depuis huit semaines sans savoir ce qu'il y a dessous.

    Ce qu'il y a dessous, c'est `PlayerPrefs`. On l'ouvre aujourd'hui — non pas parce que la case ne suffit pas, mais parce que **dès que tu écris ton propre script**, c'est l'outil dont tu as besoin : la case coche une Variable du CES, elle ne sauvegarde pas ce que ton code à toi calcule.

### `PlayerPrefs` : trois clés suffisent

`PlayerPrefs` est un petit carnet de notes que Unity garde sur le disque : à chaque **clé** (un nom) correspond une **valeur**. Le carnet survit à la fermeture du jeu.

| Clé | Valeur |
|---|---|
| `DernierNiveau` | `"Zone2"` |
| `MeilleurScore` | `42` |
| `VolumeMusique` | `0.6` |

Trois types seulement : `int`, `float` et `string`. Un `bool` se range en `int` : `1` pour vrai, `0` pour faux.

!!! info "Où vont les données?"
    Sur Windows, dans le registre du système. Dans un navigateur, dans le stockage du site : la sauvegarde suit le navigateur, pas le joueur. L'éditeur et le build ont **chacun leur propre** sauvegarde.

### `SetInt`, `SetFloat`, `SetString`, `Save`

```c#
// Écrire
PlayerPrefs.SetInt("MeilleurScore", 42);
PlayerPrefs.SetFloat("VolumeMusique", 0.6f);
PlayerPrefs.SetString("DernierNiveau", "Zone2");
PlayerPrefs.Save();                                   // Écrit sur le disque tout de suite

// Lire : la deuxième valeur est celle par défaut, si la clé n'existe pas encore
int record = PlayerPrefs.GetInt("MeilleurScore", 0);
float volume = PlayerPrefs.GetFloat("VolumeMusique", 1f);
string niveau = PlayerPrefs.GetString("DernierNiveau", "");

// Vérifier
if (PlayerPrefs.HasKey("DernierNiveau")) { /* Il y a une partie à continuer */ }
```

!!! warning "`Save()` après une étape importante"
    Unity écrit les `PlayerPrefs` sur le disque à la fermeture normale du jeu. Un plantage, un onglet de navigateur fermé brusquement : tout est perdu. Appeler `PlayerPrefs.Save()` juste après avoir enregistré une progression ou un record.

!!! tip "Le nom de la clé"
    Une faute de frappe dans une clé ne produit **aucune erreur** : `GetInt("MeilleurScor")` renvoie simplement la valeur par défaut. Écrire la clé une seule fois, dans une constante, et réutiliser la constante.

### `DeleteAll` : comment tester une sauvegarde

Pour tester le jeu comme un nouveau joueur, il faut effacer la sauvegarde :

| Moyen | Effet |
|---|---|
| Menu **Edit > Clear All PlayerPrefs** | Efface toute la sauvegarde **de l'éditeur** |
| `PlayerPrefs.DeleteKey("MeilleurScore");` | Efface une clé |
| `PlayerPrefs.DeleteAll();` | Efface tout. Utile derrière un bouton **Réinitialiser** des options |

### Ce qu'on sauvegarde : progression, options, meilleur score

| Quoi | Exemple | Recette |
|---|---|---|
| **Options** | Le volume de la musique | Déjà fait : `SliderVolume.cs` du [menu Options](#le-menu-options-le-volume) |
| **Progression** | Le dernier niveau atteint, et un bouton **Continuer** dans l'accueil | `Progression.cs` |
| **Meilleur score** | Le record, affiché dans l'écran de fin | `MeilleurScore.cs` |

#### La progression

On sauvegarde le **niveau** atteint, pas l'état de la partie : en continuant, le joueur reprend au début du niveau, sans son inventaire. Pour un jeu de trois niveaux, c'est suffisant.

```c# title="Progression.cs"
using UnityEngine;
using UnityEngine.SceneManagement;

public class Progression : MonoBehaviour
{
    const string CLE = "DernierNiveau";

    [Tooltip("Coché dans les scènes de niveau : la scène s'enregistre à son ouverture. Décoché dans l'accueil.")]
    public bool enregistrerCetteScene = true;

    [Tooltip("Dans l'accueil seulement : le bouton Continuer, caché s'il n'y a pas de sauvegarde")]
    public GameObject boutonContinuer;

    void Start()
    {
        if (enregistrerCetteScene)
        {
            PlayerPrefs.SetString(CLE, SceneManager.GetActiveScene().name);
            PlayerPrefs.Save();
        }

        if (boutonContinuer != null)
            boutonContinuer.SetActive(PlayerPrefs.HasKey(CLE));
    }

    // Bouton Continuer
    public void Continuer()
    {
        SceneManager.LoadScene(PlayerPrefs.GetString(CLE));
    }

    // Bouton Nouvelle partie : écrire le nom de la première scène dans le champ du On Click
    public void NouvellePartie(string premierNiveau)
    {
        PlayerPrefs.DeleteKey(CLE);
        SceneManager.LoadScene(premierNiveau);
    }
}
```

**Dans chaque scène de niveau**

1. Dans la **Hierarchy** : clic-droit **Create Empty**, le nommer `Progression`
1. Y ajouter `Progression.cs` : **Enregistrer Cette Scene** coché, **Bouton Continuer** vide

**Dans l'accueil**

1. Dans le **Canvas**, ajouter un bouton **Continuer** à côté de **Jouer**
1. Créer un objet vide `Progression` avec `Progression.cs` : **Enregistrer Cette Scene** **décoché**, glisser le bouton **Continuer** dans **Bouton Continuer**
1. **On Click** du bouton Continuer → `Progression.Continuer`
1. **On Click** du bouton Jouer → `Progression.NouvellePartie`, et écrire le nom de la première scène dans le champ

!!! warning "La scène de fin"
    Ne pas placer `Progression` (coché) dans les scènes **Fin** et **Crédits** : le bouton Continuer y renverrait le joueur.

#### Le meilleur score

Le score vient du script `Resource` du [cours 7](./cours07.md#ressources). À la victoire, le CES demande à `MeilleurScore` de comparer le score au record.

```c# title="MeilleurScore.cs"
using UnityEngine;
using UnityEngine.Events;
using TMPro;

public class MeilleurScore : MonoBehaviour
{
    const string CLE = "MeilleurScore";

    [Tooltip("La ressource qui compte les points (script Resource). Vide dans l'écran de fin.")]
    public Resource ressource;

    [Tooltip("Texte qui affiche le record (facultatif)")]
    public TMP_Text texteRecord;
    public string format = "Record : {0}";

    public UnityEvent onNouveauRecord;

    void Start()
    {
        Afficher();
    }

    // À appeler par le CES (Invoke Events) au moment de la victoire
    public void Comparer()
    {
        int score = ressource.Amount;
        if (score > PlayerPrefs.GetInt(CLE, 0))
        {
            PlayerPrefs.SetInt(CLE, score);
            PlayerPrefs.Save();
            onNouveauRecord.Invoke();      // Son, particules, texte « Nouveau record! »
        }
        Afficher();
    }

    void Afficher()
    {
        if (texteRecord != null)
            texteRecord.text = string.Format(format, PlayerPrefs.GetInt(CLE, 0));
    }
}
```

1. Dans le dernier niveau : un objet vide `MeilleurScore` avec le script, glisser l'objet qui porte `Resource` dans **Ressource**
1. Sur le CES de la victoire, ajouter une action **Invoke Events** : **MeilleurScore > Comparer ()**, **avant** le changement de scène
1. Dans la scène **Fin** : un autre objet `MeilleurScore`, **Ressource** vide, un texte TextMeshPro glissé dans **Texte Record**

!!! example "Variante : le meilleur temps"
    Pour un jeu chronométré, le meilleur est le plus **petit** : remplacer `GetInt` / `SetInt` par `GetFloat` / `SetFloat`, la valeur par défaut par `9999f`, et le `>` par `<`.

!!! note "Contenir l'ambition"
    `PlayerPrefs` suffit. Ton jeu a un niveau et une mécanique — il n'y a rien à sérialiser qui ne tienne pas dans trois clés. JSON existe pour les états complexes, les chemins de fichiers, les versions de sauvegarde et la corruption de données. C'est un sujet de session avancée.

## La performance

!!! note "En survol"
    L'objectif n'est pas d'optimiser, c'est de savoir **où regarder** quand le jeu rame, surtout dans le navigateur.

### Le Profiler, en survol

**Le panneau Stats**

Dans la vue **Game**, bouton **Stats** (en haut à droite). Lancer le jeu et surveiller :

| Valeur | Lecture |
|---|---|
| **FPS** | Images par seconde. Viser `60`; sous `30`, le joueur le sent |
| **Batches** | Le nombre de « commandes de dessin » envoyées à la carte graphique. Moins, c'est mieux |
| **Tris** | Le nombre de triangles affichés |

**Le Profiler**

1. Menu **Window > Analysis > Profiler**
1. Lancer le jeu : le graphique **CPU Usage** défile
1. Repérer un **pic** (une saccade), cliquer dessus : le jeu se met en pause sur cette image
1. En bas, la vue **Hierarchy**, triée par **Total** : la ligne du haut est ce qui a coûté le plus cher. Un nom de script de son cru tout en haut? C'est probablement un `Update()` qui en fait trop

### Le *batching*

Chaque objet dessiné coûte une commande à la carte graphique. Le *batching* regroupe plusieurs objets en une seule commande.

- **Static** : en haut à droite de l'**Inspector**, cocher **Static** sur tout le décor qui ne bouge **jamais** (murs, sol, rochers, maisons). Unity fusionne ces objets au build. Ne pas cocher un objet animé, une porte qui s'ouvre ou un objet ramassable
- **Un même material** : les packs Synty utilisent une seule texture (un *atlas*) pour tout le pack, donc un seul material. C'est idéal : éviter de dupliquer ce material pour chaque objet
- Le **SRP Batcher** de l'URP est déjà actif : rien à faire

### Le nombre de lumières temps réel

Une lumière temps réel qui projette des **ombres** est ce qui coûte le plus cher, surtout sur le Web. Une **Point Light** avec ombres coûte jusqu'à six fois plus qu'une **Directional Light** : elle calcule ses ombres dans toutes les directions.

| Règle | Où |
|---|---|
| Une seule lumière avec ombres en temps réel : le soleil (**Directional Light**) | **Inspector** de la lumière > **Shadow Type** |
| Les autres lumières : **Shadow Type** = `No Shadows` | **Inspector** de la lumière |
| Les lumières qui ne bougent pas : **Mode** = `Baked`, puis précalculer l'éclairage (voir le [cours 8](./cours08.md)) | **Inspector** de la lumière, fenêtre **Window > Rendering > Lighting** |
| Une **Range** pas plus grande que nécessaire | **Inspector** de la lumière |

### La taille des textures

Une image importée en 4096 × 4096 pèse jusqu'à 16 fois plus qu'en 1024 × 1024, pour une différence souvent invisible à l'écran.

1. Dans le panneau **Project**, sélectionner la texture
1. Dans l'**Inspector**, **Max Size** : `1024` pour un objet, `512` pour un petit objet ou une icône du HUD
1. Cliquer **Apply**

**Et le son**

Une musique en `.wav` pèse facilement 40 Mo. Dans le panneau **Project**, sélectionner le clip; dans l'**Inspector** :

| Réglage | Musique et ambiances | Effets courts |
|---|---|---|
| **Load Type** | `Streaming` | `Decompress On Load` |
| **Compression Format** | `Vorbis` | `Vorbis` ou `ADPCM` |
| **Quality** | `50` à `70` | — |

!!! tip "Qu'est-ce qui pèse dans le build?"
    Après un build, dans la **Console** : menu **⋮** > **Open Editor Log**, puis chercher `Build Report`. La liste des fichiers les plus lourds du jeu apparaît, du plus gros au plus petit. Souvent : une musique, une texture oubliée, un pack importé au complet.

## Pratique

L'ordre compte : un build Web bloque Unity pendant de longues minutes. On règle tout **avant** de le lancer.

1. **Player Settings** : nom, version, icône, `1280` × `720` pour le Web, **Decompression Fallback** coché
1. **Scene List** : toutes les scènes, l'accueil en premier
1. Cacher le bouton **Quitter** sur le Web (`CacherSurWeb.cs`)
1. *Recommandé :* **Build Windows** dans `Builds/Windows`, puis jouer du début à la fin
1. **Switch Platform** vers **Web**, puis **Build** dans `Builds/Web`. ⏳ Pendant ce temps :
    - Compléter le README : concept, commandes, crédits
    - Monter la page itch.io minimale : titre et commandes
1. Téléverser le `.zip` du build Web, régler l'*embed*, puis jouer dans le navigateur, **son compris**
1. Faire tester la page par un voisin, depuis **son** poste
1. Le temps restant : menu pause, menu Options, sauvegarde
